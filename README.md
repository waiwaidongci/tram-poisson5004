# 有轨电车路口阻断计数预测

按实际过车量校准阻断风险，给下一轮路口巡查排班。

澄浦有轨电车 2 号线行车调度组，负责港湾路与科创大道沿线的四处平交路口。 调度员将信号系统过车量与值班员确认的阻断事件按路口、日期、时段合并成 CSV，信号台停测单单独导入并与逐窗观测跨系统对账。班前会上用训练期检出全线阻断率断点、用留出期检验末段计数预测，将道路负荷和具体路口交给信号班与沿线巡查员。

- 直接比较阻断次数，会把车次多的路口排得过高。
- 停测窗口若当成零阻断，会拉低每车次阻断率的估计。
- 阻断率换档后仍用全程均值，留出评分和巡查排班都会失真。

## 业务模块

| 模块 | 用途 |
|---|---|
| 行车调度总览 | 查阅业务口径、当班流程及最新运行。主管可以核对审计记录。 |
| 过车与阻断台账 | 下载「澄浦2号线过车与阻断_20261107-20.csv」与停测单模板并核对字段。分析员可导入 UTF-8 CSV，保留数据指纹和原始行。 |
| 阻断模型试算 | 选择批次和参数（留出日数、断点罚分、重点阈值）并提交后台计算，可从运行列表追踪状态。 |
| 路段与路口风险 | 核对全线断点、停测剔除窗口和留出评分，通过来源链接回查数据。 |
| 巡查排期复核 | 查看待处理或已完成记录。复核主管可提交巡查排期复核及依据。 |
| 排班依据导出 | 按批查找结果，核对复核状态并下载相应的 CSV。源数据更新后旧结论立即失效，重算完成才出新依据。 |

## 演示流程

1. 11 月 21 日 08:10，汇总 11 月 7–20 日的过车与阻断值班记录，并取回信号台停测单。
2. 在「过车与阻断台账」导入「澄浦2号线过车与阻断_20261107-20.csv」与停测单，确认 111 个观测窗口和 4 条停测记录。
3. 在「阻断模型试算」设定留出最近 3 个观测日、断点罚分 12，重点阈值填每百车次 9 次。
4. 在「路段与路口风险」核对全线断点日期、停测剔除窗口和 11 月 18–20 日留出评分。
5. 查看各段分路口每百车次阻断率，再按路段和路口核对同等过车量下的预计阻断次数。
6. 在「巡查排期复核」记录要跟进的路口和相应时段，交由信号班确认排班。
7. 在「排班依据导出」下载 CSV，随值班交接单保存验证明细与巡查清单。

## 计算口径

- 一行是一个日期、道路、路口、时段的观测窗口。阻断次数为确认事件数，暴露量为同窗口实际过车车次。
- 信号台停测单按日期、道路、路口、时段与逐窗观测对账；停测窗剔除出拟合与评分，不计为零阻断，无对应观测的停测记录也会列出。
- 按日期整组留出最近若干观测日。仅用训练日搜索全线共用断点，每段每个路口至少三天有效观测。
- 每段分路口拟合每车次阻断率（阻断数÷过车车次），目标为训练期泊松偏差加每个断点的罚分，取全局最小；打平时选断点更少、日期更早的方案。
- 留出期只用末段阻断率预测，逐窗报告泊松偏差，越低越好。
- 巡查表以留出期过车量编制同等工作量情景，按每百车次预计率达到阈值为重点、两倍阈值为优先。源数据更新后旧结论立即失效，重算完成才导出新的排班依据。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | MySQL 8 存储批次、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
